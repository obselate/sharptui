Chapter 1

Run a retained tree

1.1

Operating principle. SharpTUI retains a tree. Construct it once. Mutate the same objects when state changes. Draw the tree into a Screen after each event batch.

Caution

Do not rebuild the tree in Draw. Do not draw application state only into a status line. Change the widget that owns the state.

1.2

App.Run(root Box) owns the terminal session. It runs until a handler returns EventResult.Exit or a fallback quit gesture matches. New apps use Escape and Ctrl+C as fallback quit gestures.

TypeRoleOperating fact
AppTerminal loopRuns a Box tree or a custom View.
BoxRetained nodeEvery drawable control and container derives from it.
RowHorizontal containerLays children on the row axis.
ColumnVertical containerLays children on the column axis.
ScreenCell frameReceives clear, write, fill, and border calls.
1.3

CellLength.Cells(20) uses a fixed 20-cell width. Its count must be 0 or more. GrowWeight distributes spare space only within its immediate in-flow parent.

Operate through a view

2.1

View is for an application that owns state and a retained tree. Draw(screen) paints one frame. Handle(ev) returns Continue, Handled, or Exit.

ResultMeaningNext stage

HandledThe view consumed the event.Routing stops.
ExitThe app must stop.The loop exits.

Route and schedule work

2.2

The app offers BeforeWidgets first. The view receives an event only when that phase declines it. Inside a custom view, route the retained root before view fallback shortcuts. Mutating value.Text retains the new state.

2.3

App.StartWorker[T](work) owns one background operation and returns its terminal state to the application loop. Use App.Post(work) for results from external producers. App.RequestDraw() requests one coalesced repaint.

Routing and update register

OperationOwnerRequired order
BeforeWidgetsApplication keymapRun before the view.
View.Handle(ev)Application viewRoute the root before view fallback shortcuts.
AfterWidgetsApplication keymapRun after the view returns Continue.
QuitGesturesApplication loopRun last.
StartWorker[T]Application loopOwn background work and terminal delivery.
App.Post(work)External producerDeliver results to the loop.
RequestDraw()Application loopRequest a draw when input did not.

Normal operating sequence

  1. Offer BeforeWidgets application commands.
  2. Call View.Handle. A custom view routes its retained root before its fallback logic.
  3. Offer AfterWidgets only after the view returns Continue.
  4. Offer QuitGestures last.
  5. Draw the next dirty frame after accepted state changes.
Caution

Use App.StartWorker for app-owned work. Return external results through App.Post. Never mutate the retained tree from a worker thread.

SharpTUI Operator's Manual Verification

Chapter 3

Test the operating path

3.1

TestDriver runs a Box tree or View without a terminal or clock. Its width and height are terminal cells. Both values must be 0 or more.

MethodResult
Send(ev)Routes one event through the normal application pipeline.
Pump()Runs posted work and samples animations at the current time.
Draw()Paints and returns the ANSI diff.
Resize(width, height)Changes the deterministic screen size.
Advance(elapsed)Moves caller-controlled time forward.
3.2

The driver exposes its App, Screen, current NowMilliseconds, and the focused element for a driven tree.

Standard verification sequence

  1. Construct the retained tree or state-owning view.
  2. Create the driver with a fixed cell width and height.
  3. Send the same event used during terminal operation.
  4. Draw the frame and inspect the resulting screen state.
  5. Advance caller-controlled time only when the test requires it.
Note

A driver test uses the application routing path. It is not a separate widget simulation.

Appendix A

Operating prohibitions

The following conditions cause incorrect ownership, routing, or rendering behavior. Observe each prohibition during application construction and maintenance.

  • A-01Don't recreate widgets to show a value change. Mutate the retained widget.
  • A-02Don't mutate the tree from a background thread. Use App.StartWorker for app-owned work or App.Post for external results.
  • A-03Don't omit screen.Clear() before drawing a custom View unless the view deliberately owns every cell.
  • A-04Don't return Handled for an event the view did not consume.
